## 3.6.0 (2026-10-17)

### Added
- **A Look and style section in the clawdify guide, and `build/preview edges`.** The guide now says in one place how characters and places are drawn: Clawd in costume on four legs, flat pixel art lit from the front-left with two or three tones per material, no hand-drawn silhouette outline (the app adds it), body and props fully opaque with see-through kept for glows and smoke and never half-opaque along an edge, solid art at least a pixel inside the frame in every pose and moment (with what eats into that room: breathing, hops, hovering, raised weapons), what may leave the frame on purpose, and how places keep the crew readable. The new Preview mode `edges` checks the frame rule: it draws characters at 80 moments of every state and 40 of every habit and signature move, and lists each state where solid art touches the top or a side, with a picture of the first such moment. The guide's verification steps and the README's Check it line mention it.
- **A redesigned Settings window, with an About tab.** Settings is now a tab per part in the toolbar, as macOS's own settings windows are: General, Window, Desktop, AIs, Screen Saver and About, each with its icon. Labels sit on the left, lined up against their controls, related settings are grouped between lines, and the window remembers which tab was open. About is laid out as macOS apps' own: the icon on the left, and beside it the name, the version, **Check for Updates…**, **What's New** (the changelog) and **Website** (the GitHub repo), a **Thanks to** list of the people whose pull requests were merged, each linked to their GitHub profile and followed by the universes they made, if any (someone who fixed a bug or added a feature is thanked by name alone). Henrik Andersen is the first, with Clawd of the Rings. The list is in the code (`OverlayController.collaborators`, to add to when merging a PR), so About never goes online by itself, and `CONTRIBUTING.md`'s maintainer checklist now ends with adding the author there. Below it are the copyright and the MIT licence. Check for Updates asks GitHub for the latest release when you click it (Clawd Clash never checks on its own) and offers the download, or the `brew upgrade` line if you installed with Homebrew.
- **Clawd Clash's social preview has every universe.** The pop-art cover GitHub shows when the repo is shared (`docs/social-preview.png`, from `Tools/MakeSocial`) had five panels, from before Stevie Clawdberg and Clawd of the Rings. It now has seven: Indiana Bones against René Bellock, and Gandclawd the Grey against the Ballrog.
- **A guard for pull requests** (`scripts/pr-guard.py`, run on every PR by `.github/workflows/pr-guard.yml`). A universe is Swift compiled into the app, so a malicious one could use the app's Accessibility grant or rewrite the AIs' hooks. The guard reads a PR with git as plain text, never building or running it, and:
  - **sorts every changed file** into green (a universe's own folder, the docs' pictures, README, CHANGELOG), yellow (passes, listed for the maintainer to read closely: registration files and the rest of the app) and red (fails: build and release scripts, dotfiles such as `.github/` and `.claude/`, instructions for AI assistants, the hook and the code compiled into it, `HookInstaller`, `SaverInstaller`, `Jump`, `main.swift`, new core files, symlinks, executables);
  - **checks the Swift lines a PR adds to a universe folder**: no file, process, network, other-app, environment or app-internal APIs (including a call hidden in a string's `\( )`, or a backticked name), only the four imports drawing needs, no attributes such as `@_silgen_name`, no `#if` or macros, no `main.swift`;
  - **blocks shadowing**: a new non-private top-level name must start with the universe's prefix and must not reuse a name from the app's own code, and extensions are allowed only on `Scenes`, `Location`, `Cast` and the universe's own types, with no added conformances. That stops a one-line `func chmod` in an art file from silently switching off the state folder's permission fix;
  - **refuses hidden code**: invisible and text-direction Unicode, non-ASCII outside strings and comments, code after a long run of spaces, lines over 260 characters, universe files over 2,000 lines;
  - **checks cast ids**: no universe has more villains than the hero ids leave room for, or more heroes than fit before the next universe's ids. This replaces the cast-size `assert`, which release builds compile out.

  CI uses `pull_request_target`, so it's always main's copy of the guard that runs, and a PR can't edit the guard to pass itself. It has a read-only token and no secrets. Run it locally with `python3 scripts/pr-guard.py <PR number>` or `python3 scripts/pr-guard.py main <branch>`. Tested against Clawd of the Rings' PR #3, where it flags the hook-side `StatusStore.swift` and `llms.txt` changes and seven unprefixed names, and against a fake malicious universe, where all 24 planted tricks were caught.
- **`.github/CODEOWNERS`** names the maintainer on every path, for main's ruleset to require that review.
- **`CONTRIBUTING.md`**: what a pull request may change and why. It lists the guard's green, yellow and red files, the rules for universe code (APIs, imports, prefixed names, extensions, layout, ids) and how to run the guard on your own branch. A section for the maintainer covers reviewing a PR: read the guard's report, never start an AI assistant or plain `./build.sh` in an unreviewed checkout, and try it with `./build.sh --untrusted`. The README's Contributing section links to it, the clawdify guide says to prefix or privatise top-level names, puts driving rides in `Ride.drives`, and says which files to leave to the maintainer when sending a PR from a fork, and `llms.txt` describes the guard.

## 3.5.1 (2026-10-16)

### Added
- **`./build.sh --untrusted`, for trying someone's pull request.** It builds into `build/` only and signs ad hoc, so the copy gets none of the permissions you've given the installed app (Accessibility, Automation). It doesn't install it, launch it, or touch any AI's hooks: read the changes, then open `build/Clawd Clash.app` yourself. Plain `./build.sh` installs, rewrites hooks and launches with your Accessibility grant, which is the wrong thing to do with code you haven't reviewed. In the README's build section and `llms.txt`.

### Changed
- **Every build has the hardened runtime**, not only releases. Local builds (`./build.sh`, `--no-install`, `--untrusted`) are signed with `--options runtime` and the Apple Events entitlement, so another program running as you can't load its own code into the app with `DYLD_INSERT_LIBRARIES` and use the app's Accessibility grant. Click-to-jump works as before.
- **Apple silicon only.** Clawd Clash is built for Apple silicon (arm64) alone from now on; 3.5.0 was the last release for Intel Macs. Release builds no longer compile everything twice and glue the halves together with `lipo`, so `./release.sh` takes about half as long, and the zip is smaller. The Homebrew casks now say `depends_on arch: :arm64`, so on an Intel Mac brew refuses the upgrade with a clear message instead of installing an app that can't open; Intel users keep 3.5.0. The README's requirements, `llms.txt` and the clawdify guide just say Apple silicon, without mentioning Intel.

### Fixed
- **A release can no longer go out un-notarized by accident.** `release.sh` used to treat any `notarytool` failure, a network blip or a locked keychain included, as "no profile", and ship without notarization; the cask then clears the quarantine flag, so brew users would have skipped Gatekeeper without anyone noticing. Now a missing profile stops the release unless you pass `--no-notarize`, and a profile that's there but fails always stops it. The check runs before the build, so it fails in seconds, not after one.
- **`release.sh` is harder to break halfway.**
  - The version must be `X.Y.Z` (it goes into the tag, the cask, the plists and a regex).
  - `gh` must be signed in before anything starts.
  - "Not found" and "couldn't check" are told apart for the tag and the release, so a network error no longer reads as "absent".
  - The app's signature is verified, and when notarized the stapled ticket and Gatekeeper's verdict too, before anything is published.
  - With `--force`, the release's zip and notes are swapped in place instead of the release being deleted first, so the cask's download URL never points at nothing.
  - An existing tap that fails to clone stops the release, instead of an empty repo being pushed in its place.
  - Old releases are pruned last, after the cask push, sorted by version rather than date, so re-releasing an older version never prunes the newest.
  - The tap's temporary folder is removed even when the script fails.
- **`brew uninstall --zap` also removes the screen saver's options**, kept in the screen saver host's container (`Clawd Clash Saver/options.json`).
- **Your prompts are no longer readable by other accounts on the Mac.** The hook keeps clipped copies of your prompts, the AI's replies, session titles and the start of each command in `~/.claude/clawd-clash/state.json`, and that folder and its files were created with default permissions (0755 and 0644), so another user account on the same Mac could read them, though Claude Code keeps the originals in an owner-only folder. `StatusStore.withLock` now sets the folder to 0700 on every write (tightening existing installs on their next hook event) and writes `state.json`, `state.json.corrupt` and `state.lock` as 0600. The hook, the app and the screen saver all run as you, so nothing else changes. Found by a Claude Security scan.
- **`--jump` and `--ax-dump` are left out of normal builds.** These click-to-jump diagnostics ran with the app's Accessibility and Automation permissions for whatever launched the app, so any program running as you could start Clawd Clash with them and read the window and tab titles of other apps. They are now compiled only into a `./build.sh --dev-tools` build, which is off by default and refused together with `--release`; plain `./build.sh`, `--no-install` and releases don't answer them. Click-to-jump itself is unchanged. Found by a Claude Security scan.
- **A `--dev-tools` build can no longer be installed or released.** `./build.sh --dev-tools` used to be refused only with `--release`, so a plain `./build.sh --dev-tools` installed the diagnostics build into /Applications, where it kept the app's Accessibility grant. It now has to go with `--no-install`. Its two reports start with "Clawd Clash dev-tools build, never ship this one", and `release.sh` stops if that text is anywhere in the release binary. `Jump.dump`, which only `--ax-dump` uses, is compiled only into those builds too.
- **Connecting an AI can no longer wipe its settings file.** `HookInstaller` read any settings file it couldn't open (one left root-owned by `sudo claude`, say) as empty, then wrote its hooks over it, losing everything else in the file: permissions, model, plugins. Now only a missing file counts as empty; any other read error stops the install for that AI and says which file. The backup it makes before its first change (`.before-vader`, `.before-clawd-clash`) used to fail silently; now a failed backup stops the change too.
- **Disconnecting no longer removes hooks that aren't ours.** A hook counted as Clawd Clash's whenever its command merely contained `clawd-clash-hook` (or an old app's hook name), so your own `my-clawd-clash-hook-wrapper` would be removed with ours. Now the command has to run a file with exactly that name.
- **Everything Clawd Clash writes is yours alone.** The hook and the app now run with `umask 077`, so every file they create is owner-only: the state, the screen saver's feed (`screensaver.json`), and the AIs' settings files they rewrite. The feed's folder in Application Support is also tightened to 0700 once per launch, for folders made 0755 by earlier versions. The feed holds the same prompts and project names as `state.json`; it was only covered by `~/Library` being owner-only.
- **The hook reads at most 16 MB of an event, and at most 1 MB of a `.git/config`.** An event bigger than that (a huge tool response) is skipped rather than held in memory, and an oversized git config is treated as no remote. Both run on every event, inside every AI session.
- **A Homebrew upgrade no longer fails when the old app can't run.** brew's uninstall step runs the installed app with `--uninstall-hooks`; when macOS refused to run that copy ("Apple could not verify…") and killed it, the whole upgrade stopped with "terminated by uncaught signal KILL". The casks now mark that step `must_succeed: false` (`release.sh`), so the upgrade carries on and the hooks just stay, pointing at the path the new app is installed to. The four casks in the tap are already patched, but brew uninstalls with the cask file saved at install time, so this protects installs made from now on; an install from before can still hit it once, and deleting `/Applications/Clawd Clash.app` and running `brew install --cask --force clawd-clash` gets past it.

## 3.2.0 (2026-10-15)

### Added
- **pi.** Clawd Clash can show [pi](https://github.com/badlogic/pi-mono) sessions, whichever model pi runs (Mistral, GPT, Gemini, local models…), with a pink outline and the model's name on the character. pi has no hooks, so connecting it writes a small extension of Clawd Clash's own to `~/.pi/agent/extensions/clawd-clash.ts`, which sends pi's events (session start and end, the prompt, each tool, the reply, compaction) to the hook; sessions already open load it after `/reload`.
